How we decided · Three-lens scoping 01 / 05

A coordinator, not a dashboard.

FleetGraph notices what's drifting, drafts the fix, and never rewrites your plan without asking.

Acts alone

Surface findings, post attributed comments, answer chat.

Additive, visible, reversible by ignoring.
Asks first

Anything that rewrites a person's plan.

Reassign, move, change state or dates.
Never

Delete, auth changes, outside communication.

The executor has no such verbs — not a prompt rule; the code physically can't.

The decision process: every scope choice went through three lenses — economics (worth building?), psychology (will a human want it?), technology (does the data exist?). Seven discovered use cases became five built ones: the graded table requires a real trace per row, so we define exactly what we can prove.

How we decided · Psychology lens × the data model 03 / 05

Events for what happens. A clock for what doesn't.

Graded test: create an unassigned issue, start the stopwatch. Card visible in ≈ 2–3 minutes against a 5-minute goal.

0:00 · created 1:30 · grace ends ≈2:30 · card visible 5:00 · goal 90s grace window 30s settle ~15s run buffer

Why wait 90 seconds? The psychology lens collided with a data-model fact: every new issue is born "Untitled" and empty while someone types. An agent that fires instantly nags people mid-keystroke — so we spend 90 of our 300 seconds on manners, and the card prints its own grace window, so the demo explains itself.

How we decided · Game theory + behavioral economics 04 / 05

It earns the right to interrupt.

Alerting is a repeated game: every false alarm spends trust the agent never gets back. Competitors use static thresholds set by an admin. FleetGraph keeps score of its own usefulness — per person — and interrupts less when it's been wrong.

  • Friction asymmetryStill on it is the cheapest button on the card: one tap, resets the clock, notifies nobody. Clearing a false alarm must cost less than learning to ignore the agent.

  • Incentive compatibilityReport a slip before the detector finds it, and it's a recalibration, not a failure. Hiding bad news stops paying.

The decision process: we treated notifications as a mechanism-design problem, not a settings page. Critical severity always gets through; the math has guards so the agent can never talk itself into permanent silence.

How we decided · Blind red team 05 / 05

We attacked this design before writing code.

A critic with zero context got the spec and orders to break it. It found three real problems in our own infrastructure — each verified against the repo, then folded into the plan.

A Week-4 deploy defect would have silently eaten the agent's database tables on Render — fixed Day 1, before any agent code.

✕

Deploy-on-push contradicted our own "CI-gated deploys" claim — now: no green CI, no deploy.

✕
