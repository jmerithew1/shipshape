Architecture defense · Mon Aug 11 · 13:00 CT · James Merithew

SHIP → PLATFORM

If someone who has never seen Ship can install the SDK, log in, create a document, and get a verified notification back — from the docs alone, in under 30 minutes — the platform works. CI proves it on every change.

TTFE CI <60s HUMAN ≤30min FLAKE 0% / 20 runs SPEC PARITY 100% PLATFORM LLM CALLS 0
01

One gate, one shape, one spec

New OAuth logins flow into the access check Ship already has — one place decides who's allowed. The API docs are generated from the code itself, and the SDK is checked against them on every build.

02

One Postgres table is the whole webhook system

Every delivery is a database row — status, attempts, next retry. The table is the queue. Each delivery is signed, so the receiver can verify it came from Ship, unchanged.

03

The agent walks in the front door

Last week the agent had a shortcut straight to the database. This week it logs in like any developer — limited permissions, rate limits, every action recorded. My own agent becomes a test of the platform.

04

Terraform is the recipe; Render is the kitchen

Three resources describe the whole deployment — terraform apply from a clean machine is the deploy, and destroy-and-rebuild is already proven. Least-privilege tested where the code actually touches AWS (production secrets): allow proven, deny proven, zero contact with the live deploy.

  • -/+ means replace. Find the attribute that forces it, then walk right along the spine.
  • ~ on env vars still deploys. DATABASE_URL changes because postgres changed, not because someone typed it.
  • starter → free looks harmless. Idling silently kills the cron and the webhook poller.
05

Deliberately not built

No message queue — one server doesn't need it, and the seam is there for later. No rewriting code that already works. No AI for AI's sake. Scope was chosen, not defaulted into. If time runs short: the CLI login gets simpler — the core loop stays.
