Architecture Defense · Monday Aug 11, 1:00 PM CT · James Merithew

PlugForge: Ship stops being an app and becomes a platform

The grade is one loop: a stranger goes from pnpm install @ship/sdk to a verified signed webhook in their terminal in under 30 minutes — scripted in CI in under 60 seconds. Every choice below exists to make that loop short and provable.

1

One gate, one shape, one spec — the contract can't drift

0:00–1:15

OAuth 2.0 hand-rolled — Auth Code + PKCE for the browser, Device Grant for the CLI — on the token patterns this repo already trusts. OAuth tokens flow through the same bearer validator that guards the API today: one gate, one revocation path. Every public failure is one ApiError shape; the OpenAPI 3.1 spec is generated from route metadata, and the SDK is parity-diffed against it in CI.

Why hand-rolled? No library implements the Device Grant — the hard part was ours either way — and the easy part (PKCE S256) is five lines of crypto. Why generated? A hand-written spec lies within a week; a generated one structurally can't.

Receipts: api/src/middleware/auth.ts (existing bearer path) · oauth-state.ts (proven one-time-consume) · fitness test enumerates every v1 route

2

Webhooks: one Postgres table is queue, retries, DLQ, and log

1:15–2:15

Stripe-style t=,v1= HMAC signatures. Retry ladder 1s→30m with jitter, 4xx dead-letters, replay keeps the original Idempotency-Key. All of it is rows in webhook_deliveries — the required retry schedule forces persistence anyway, so the persistence is the queue.

Why no Redis/broker? Single-instance deploy makes in-process delivery correct, not just cheap — and the queue-backed deliverer stays a drop-in behind the same interface (that's the Liskov requirement, satisfied honestly). Why does webhooks tail work on a laptop? Same trust model as stripe listen: the server relays the raw signed payload; the CLI verifies the HMAC locally — the key never leaves the client.

3

The agent walks in the front door

2:15–3:15

FleetGraph (Week 5) trades its private DB pool for the public SDK, behind a feature flag — authenticating as an OAuth app (Client Credentials, first-party machine-to-machine). Same scopes, same rate limits, same audit trail as any stranger.

Why? The audit rows are the proof of the whole platform: if our own agent can live on the public API, a third party can. Cost shape unchanged — the platform makes zero LLM calls; one call per agent turn, exactly as graded last week.

Proof: Part-2 test suite passes flag-on and flag-off · agent's client_id visible in the public audit log · LangSmith before/after shows identical token volume

4

Infrastructure is the code — Terraform describes the deployment

3:15–4:15

Terraform is the recipe; Render is the kitchen. terraform/render/ declares the entire deployment — three resources — and terraform apply from a clean machine IS the deploy. Destroy-and-redeploy was proven and graded in Week 5. IAM least-privilege runs the real production secrets code path (loadProductionSecrets() → SSM) against a terraform-managed scratch — admin policy locked down to one ssm:GetParameter ARN, allow proven, deny proven, zero contact with the graded deployment.

Why Render, not an ECS stack? We defend the deployment that actually serves you, not a theater stack built for vocabulary compliance — and the gap to the brief's ECS wording is mapped openly, line by line.

Blast-radius crib — the three resources
render_project.ship ─▶ render_postgres.ship ─(DSN)─▶ render_web_service.api
  • Project env replaced → both children replaced → database destroyed (free tier, no backups) → repopulation runbook.
  • Postgres region/version → replacement → data loss; region must match the service or the private-network DSN stops resolving.
  • Service env vars → in-place, but triggers a deploy; DATABASE_URL is derived — it changes because Postgres changed.
  • Service replaced → SESSION_SECRET regenerates → every user logged out.
  • starter→free → looks harmless (~) → idling kills cron + webhook poller silently.
Read order: summary line → any -/+? name the forcing attribute → walk the spine downstream → name the risky ops → state the rollback. ~ in-place · -/+ replace · (known after apply) computed, cascades.
5

What we deliberately didn't build

4:15–5:00

Scope was chosen, not defaulted into — each cut has a one-line defense and a preserved seam for the day it's needed.

Message broker — interface preserves the swap Service-layer refactor — week-eating, zero grader value OAuth libraries — they skip the part we must build ECS side-stack — theater deployment Platform-layer AI — the brief itself calls it scope creep
